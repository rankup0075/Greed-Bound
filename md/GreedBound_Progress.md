- **5계열 명칭 확정**: 능력 강화(stat) / 행동 변화(behavior) / 증식·군세(swarm) / 환경·규칙(env) / 저주·특수(curse)
- **위험도 상한·붕괴 처리 확정**: 상한 없음. 대신 **150 이상에서 돌파(Overload)** 상태 —
  매 라운드 정예 적 1마리 추가, 보상 배수 상한 x8.0. 위험도 50마다 유물 1개 자동 획득
- **런 종료 시 골드 처리 확정**: 메타 재화 **영혼(Soul)** 으로 전환.
  `라운드 × 5 + 위험도 ÷ 8 + 유물 수 × 10` — 단, 사용처는 아직 없음(미완성)
- **상점 주기 변경**: 5라운드 → **3라운드마다** (라운드 N.5, 별도 씬)
- **수치 동결**: Spec 문서의 값은 플레이 테스트를 거친 결과이므로 임의 변경 금지.
  바꿔야 하면 Spec을 먼저 갱신한 뒤 코드를 수정

### 이후 절대 어기면 안 되는 규칙 (Spec 8·9장)

- 공격 판정 범위와 검격 이펙트 반지름을 항상 일치시킬 것 (프로토타입에서 86 vs 62로 어긋나 버그 발생)

### 화염 지대(불기둥)를 닿는 순간 피해로 + 플레이어 콜라이더 수정 (사용자 피드백)
- 사용자: 불기둥이 올라올 때만 피해가 들어오는 것 같다 → **지속 피해가 아니라, 불타는 동안 몸이 닿으면 그 순간 즉시 피해**가 맞는 설계
- 원래 동작: 0.5초마다 `damageOverTime` 피해. 타이머가 지대 밖에서도 돌아가 들락거리면 한 틱을 건너뛸 수 있었고,
  지속 피해라 **피격음·깜빡임·화면 흔들림이 전부 없어** 맞고 있는지 알 수 없었음
- **결정(사용자)**
  - 불은 **일반 피격** — 닿는 순간 즉시, 피격음·깜빡임·화면 흔들림·무적 0.767초가 생김(보복의 가시도 발동)
  - **한 방 피해는 그대로** `4 + 라운드 × 0.3`. 무적이 0.5초보다 길어 초당 피해는 예전의 약 65%가 됨(라운드10 기준 14 → 9.1/초) — 그래도 유지
- 수정
  - `FireZone` — `damageOverTime` 제거, `nextHitTime`으로 최소 간격 0.5초만 두고 무적에 막히면 다음 프레임에 다시 시도,
    판정을 보이는 사각형과 일치(`b.max.y >= 지면`), 플레이어 콜라이더 캐시·참조 재탐색
  - `HitInfo.damageOverTime`은 이제 쓰는 곳이 없음 (독·중독 같은 게 생길 때를 위해 구조는 남겨 둠)

## 2026-09-20 — 일시정지 화면이 가려지던 문제

**원인.** 일시정지를 OnGUI(`MenuGui`)에서 정식 UI 캔버스(`MenuUi`)로 옮기면서 생긴 부작용이다.
유니티는 **IMGUI(OnGUI)를 ScreenSpaceOverlay 캔버스보다 나중에** 그린다. 즉 캔버스 정렬 순서를
아무리 높여도 OnGUI 를 이길 수 없다. 예전에는 일시정지도 OnGUI 라 `GUI.depth = -1000` 으로
다른 OnGUI 위에 올릴 수 있었는데, 그 수단이 사라진 것이다.
그래서 로비·상점·튜토리얼의 월드 이름표와 말풍선이 일시정지 메뉴를 뚫고 올라왔다.

캔버스끼리의 순서는 원래부터 문제가 없었다 — HUD 100 < 카드 선택 200 = 타이틀 메뉴 200 < 일시정지 300.

**수정.**
- `LobbyManager.OnGUI` / `ShopManager.OnGUI` / `TutorialManager.OnGUI` 맨 앞에 `if (PauseMenu.IsOpen) return;`
- 일시정지 어둡기 `0.7` → `0.88` (게임 화면이 살짝만 비치도록). `PauseMenu` 의 옛 OnGUI 경로도 같은 값으로 맞춤

**앞으로.** OnGUI 로 월드 위에 뭔가 그리는 화면을 새로 만들면 **같은 가드를 반드시 넣어야 한다.**
남은 임시 OnGUI: 조작법 표, 소지품 창, 상점·로비 말풍선·이름표, 튜토리얼 안내.
이것들을 정식 UI 로 옮기면 가드는 저절로 필요 없어진다.

- [ ] 확인 필요: 로비 / 전투 / 상점에서 각각 ESC — 이름표·말풍선이 사라지고 메뉴만 보이는지
- [ ] 확인 필요: 일시정지 중 조작법(`ControlsPanel`)은 여전히 메뉴 위에 제대로 뜨는지
